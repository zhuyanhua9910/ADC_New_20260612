# WF280 测试工具

**双击 `WF280测试工具.exe` 就能用**，不用装 Python、不用敲命令、不用命令行。

> 根目录里的 `WF280测试工具_v1.2_旧版备份.exe` 是改版前的旧版本（只认旧的 10 个寄存器帧），
> 正常测试请用 `WF280测试工具.exe`；备份留着方便回退，确认新版没问题后可以删掉。

原「多功能小板测试」是编译好的 exe、没有源码，加不进 WF280 的新命令，
所以单独做了这个工具，专测 WF280 的全部功能，跟原工具并存、互不干扰。

## 第一次运行

1. 把 `WF280测试工具.exe` 拷到测试电脑任意位置（单独一个文件就行，不依赖其他文件）
2. 双击打开
3. 等 2~3 秒（单文件 exe 要先自解压，之后启动会快一些）

> 如果 Windows 提示「已保护你的电脑」，点「更多信息」→「仍要运行」。
> 这是未签名程序的常规提示，不是病毒。

## 使用流程

1. **选串口** → 插上板子后点「刷新」，选中对应的 COM 口（CH340 那类，会自动优先选它）
2. **点「连接」**（波特率和从机地址默认 115200 / 1，一般不用改）
3. 连上后顶部会显示 **「设备：固件 v1.0 · COM20 · 115200 8N1 · 从机 1」**
   —— 先看版本号对不对、是不是要测的那块板子
4. 切到「① 整套测试」，点「开始整套测试」，约 2~3 秒出结果

界面分两块，**互不影响**：

| 页签 | 内容 | 说明 |
| --- | --- | --- |
| ① 整套测试 | `cmd[0] = 14`，即固件 `AllTestFor280` | 一条命令的异步执行，跑完给出 77 个寄存器的解析结果和 PASS / NG |
| ② 单项命令 | OTP `{11}`、输出 3.3 V `0x208`、输出 1.8 V `0x210`、读系数 `0x209`、读 M1 `0x207`、轨压回读 `0x211`、设定轨压 `0x201` | 单独测某一项时用；「全 32 路」一行是 **3.3 V 读 NOR** / **1.8 V 读 M1** 两个固定 32 路按钮，不用填路数、不用先设压 |

> 「整套测试」就是固件里 `AllTestFor280` 那一条综合测试，**不是**把所有命令跑一遍。
> 电压由固件自己切：切到 1.8 V 稳定后先回读轨压再读 M1 bank，切到 3.3 V 稳定后
> 先回读轨压再读 NOR bank，上位机不用设压。

## 整套测试看什么（按界面顺序）

| 界面行 | 结果帧位置 | 说明 |
| --- | --- | --- |
| 测量整体 | `[0]` 状态 | `0` = PASS；非 0 是错误码，直接显示中文原因 |
| 轨压 1.8 V（实测） | `[1]` | mV，1.8 V 稳定后、读 M1 之前回采的 DUT 真实轨压 |
| 轨压 3.3 V（实测） | `[2]` | mV，3.3 V 稳定后、读 NOR 之前回采的 DUT 真实轨压 |
| 工作电流原始码 | `[3..4]` | 32 位原始码（低 16 位在前），括号里是 24 位有符号值 |
| 工作电流（解析） | 由原始码换算 | 上位机按固件同一公式算出的 uA，**这才是实际电流** |
| 休眠电流原始码 | `[5..6]` | 同上 |
| 休眠电流（解析） | 由原始码换算 | 同上 |
| 0xAC 原始数据 | `[7..12]` | 6 个字节：Status + 电桥 20 位 + 温度 20 位 |
| 电桥 / 温度原始码 | `[8..12]` | 原样展示 + 20 位有符号解释（`[7]` 的芯片状态字节不再判定，只在上面那行原始数据里能看到） |
| M1 / NOR 系数 | `[13..44]`、`[45..76]` | 两个 bank 各 32 路原始值，右侧表格逐路对照 |

结果帧固定 **77 个输入寄存器**，失败时固件只写首字错误码，`[1..76]` 全 0，
界面会明确写「失败帧不带系数」，并给出「失败说明 / 建议」，
不会把全 0 当成真实测量值。

> 1.8 V 那一档只做展示（落在 1800 mV ±10 % 显示 OK），总判定仍然看 3.3 V 档
> 轨压 + 32 路系数一致，产线的 PASS / NG 规则没变。

错误码：

| 值 | 含义 |
| --- | --- |
| `0x00` | OK |
| `0x01` | I2C 通讯失败 |
| `0x02` | NOR 忙等超时 |
| `0x03` | 命令响应超时 |
| `0xE1` | 电流短路 |
| `0xE2` | 轨压异常 |
| `0xE3` | M1 / NOR 系数不一致 |
| `0xF1` | 设备忙（测试进行中） |
| `0xF2` | 命令长度错误 |

## 覆盖的命令

| 功能 | 命令 | 方式 | 返回 |
| --- | --- | --- | --- |
| 固件版本 | `{1, 0x104}` | 同步 | 主版本 / 次版本 |
| 整套测试 | `cmd[0] = 14` | 异步，走 `IsTaskDone` 队列 | 77 个寄存器：状态、1.8 V / 3.3 V 两档轨压、两路电流原始码、6 字节原始数据、M1/NOR 各 32 路系数 |
| 轨压回读 | `{1, 0x211}` | 同步，随时可读 | 状态 + mV |
| OTP 校验 | `{11}` | 同步 | 1=通过 / 0xFF=失败 + 失败路号 |
| 输出测试 3.3 V | `{1, 0x208, 测量参数, 稳定时间}` | 同步 | 状态 + 6 个原始字节 |
| 输出测试 1.8 V | `{1, 0x210, 测量参数, 稳定时间}` | 同步 | 状态 + 6 个原始字节 |
| 读正常 bank 系数（3.3 V 读 NOR） | `{1, 0x209, 路数}` | 同步 | 状态 + N 路 16 位系数；固件按 bank 自动切 3.3 V |
| 读 M1 bank 系数（1.8 V 读 M1） | `{1, 0x207, 路数}` | 同步 | 状态 + 待机/工作电流码 + N 路系数；固件自动切 1.8 V |
| 设定 DAC 轨压（辅助） | `{1, 0x201, lo, hi}` | 同步 | 状态 |

命令码、结果偏移、判定阈值都对应固件 `Core/Src/wf280.c`、`Core/Inc/wf280.h`。
板子侧：USART2，**115200 8N1**，Modbus RTU 从机地址 **1**。

## 三个注意点

0. **先读版本再测**
   连上后第一件事是读 `{1, 0x104}`，正常返回 `v1.0`。
   如果读到 `0.0`，说明设备没应答或固件没烧进去，这时点测试只会拿到一堆 0。

1. **寄存器地址用 PDU 地址（0 基），不是 3xxxx/4xxxx 引用号**
   实测这块板子：**写命令 40000、读结果 30000**。
   发 40001 / 30001 会直接被固件回异常码 02（非法寄存器地址）。
   固件注释里写的「30001 起」「40001」是 Modbus 引用号写法，上线要减 1。
   工具连接时会自动试 40000/30000 和 40001/30001 两套，日志里会打印最终用的是哪套。

2. **轨压读到的是实测值，不是设定值**
   `0x211` 走 PB1/ADC1_IN9 分压回采，读到的是 DUT 真实轨压。
   「设了 3300 却读到 1200」说明轨没起来，不是命令没生效。
   整套测试结束时固件会断电，这时单点「读取轨压」看到接近 0 mV 是正常的。

## 关于电流：原始码 + 解析值

`ADS1220` 是 24 位有符号 ADC，这块板子的电流通道读出来是**负值**，
比如工作电流原始码 `0xFFFD29AE`，其实是 24 位补码 `0xFD29AE` = **-185938**，
固件按 32 位符号扩展后原样回传（高 16 位是 `0xFFFF`，只是符号位）。

固件只回传原始码，**不替上位机算 uA**；界面里的「解析值」是按固件同一套常数算的：

```
uA = |原始码| × 轨压(mV) × 1000 / (8388608 × 30)
```

`185938 × 3296 × 1000 / (8388608 × 30) ≈ 2435.2 uA`，也就是分流电阻上 73 mV 的压降，
是个正常的读数，负号只代表电流方向。原始码本身也一并列出，方便跟固件对账。

> 分流电阻以板上实测的 **30 Ω** 为准（早期按 120 Ω 记录，同样原始码会少报 4 倍）。
> 改电阻时只需同步三处：固件 `Core/Src/wf280.c` 的 `WF280_CURRENT_SHUNT_OHM`、
> `Core/Src/wf183.c` 的 `WF183_CURRENT_SHUNT_OHM`、本工具 `wf280_proto.py` 的
> `CURRENT_SHUNT_OHM`。

> 休眠电流同样按这个方式算。静止时原始码只有几十个 LSB，
> 换算出来不到 40 uA，看起来偏小，可以用万用表对比确认是否需要校准零点和增益。

## 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 连接后显示「通讯失败」 | 串口口选错，或板子没上电；换个 COM 口再试 |
| 提示异常码 02 | 寄存器基址不对（固件可能换了约定），看日志里自动识别到哪套 |
| 输出测试报「NOR 忙等超时」 | 稳定时间太短。默认 300 ms，冷启动时可以加到 500~800 ms |
| 整套测试一直等到超时 | 检查 DUT 是否插好；默认超时 60 s（正常约 2~3 s） |
| 整套测试报 0xE3 | M1 与 NOR 系数不一致；用「3.3 V 读 NOR」「1.8 V 读 M1」各读 32 路逐路比对 |
| 打不开串口（拒绝访问） | 原「多功能小板测试」还开着，先把它的串口断开或关掉窗口 |

## 源码与重新打包

界面和协议是 Python 写的，已打包进 exe，**日常使用完全不需要 Python**。
只有要改功能时才需要动源码：

```
src/
  wf280_tool.py    入口（图形界面 / 命令行）
  gui.py           tkinter 界面
  wf280_proto.py   命令封装与结果解码（77 字结果帧）
  mb_rtu.py        极简 Modbus RTU 主站（不依赖 pymodbus）
  selftest.py      离线自检（不需要板子）
build.bat          一键重新打包
```

重新打包：装 Python 3.10+（建议 3.12，跟现有 exe 用的版本一致）和
`pip install pyserial pyinstaller`，然后双击 `build.bat`，根目录会生成新的 exe。

离线自检（不需要板子，用假从机验证协议，27 项）：

```
python src/selftest.py
```

命令行用法（需要源码环境）：

```
python src/wf280_tool.py --port COM5 version
python src/wf280_tool.py --port COM5 full
python src/wf280_tool.py --port COM5 full --coeffs     同时打印 32 路 M1/NOR
python src/wf280_tool.py --port COM5 rail
python src/wf280_tool.py --port COM5 out18
```

退出码：`0` 通过、`1` NG、`2` 通讯错误，方便产线脚本判断。
